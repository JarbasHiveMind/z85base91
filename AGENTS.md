# AGENTS.md — `z85base91`

Guidance for AI coding agents (and humans) working in this repository. Read it
fully before making changes. It encodes conventions that are not obvious from the
code and that, if ignored, produce work that will be rejected.

## Repo

A binary-to-text encoding library providing three codecs — Base91, Z85B, and
Z85P — each with a fast C implementation (precompiled `.so` per architecture)
and a pure-Python fallback. Part of the
[HiveMind](https://github.com/JarbasHiveMind) ecosystem — the HiveMind mesh
uses these codecs to pack binary payloads for text-mode transports (websocket
frames, encrypted payloads) where raw bytes cannot travel safely. Consumers
include the HiveMind websocket protocol and clients across the ecosystem; the
wire protocol and specs live in the architecture docs. This is a leaf
dependency: it has no HiveMind imports of its own, but anything that changes
its output format breaks every peer that decodes it.

## Layout / build / test

- Package module: `z85base91/` (`b91.py`, `z85b.py`, `z85p.py`, `__init__.py`
  loads the `Z85P` C binding via `ctypes`, plus `bench.py` and the
  per-architecture `lib*-{x86_64,aarch64,i386}.so` binaries). C sources are in
  `src/` (`b91.c`, `z85b.c`, `z85p.c`, `compile.sh`). Tests live in `test/`
  (`test_b91.py`, `test_z85b.py`, `test_z85p.py`) — do not create a second
  test directory.
- Set up a throwaway environment inside your clone; never touch a shared venv:
  `python3 -m venv .venv && VIRTUAL_ENV=$PWD/.venv uv pip install -e ".[test]" --prerelease=allow`
- Run the suite in the foreground: `python3 -m pytest test -q`.
- `uv`, never `pip`. If latest prereleases fail to install or resolve, that is a
  bug to FIX at the source, not to work around with a pin downgrade.
- If you touch `src/*.c`, you must also rebuild and commit the matching
  `.so` files for all three architectures (see `src/compile.sh`) — a source
  change without rebuilt binaries silently ships the old codec.

## Tests

- Adversarial by default. A regression test must **fail before the fix and pass
  after** — prove it by reverting only the source (`git apply -R`, never
  `git stash` across worktrees) and watching the test flip.
- Tests must be mutation-proof: gutting the feature must fail the test. A test

## Repo-specific rules

- **Wire compat is law.** This codec's output travels the HiveMind wire between
  independently-deployed peers. `encode`/`decode` output for a given input must
  never change across a release — a changed alphabet, padding scheme, or byte
  ordering breaks every already-deployed peer that decodes frames encoded by
  this library (or vice versa). Any behavior change to an existing codec is a
  breaking change and needs a new codec name, not a silent edit.
  `encode(decode(x)) == x` and `decode(encode(x)) == x` must hold exactly for
  every codec, on both the C path and the pure-Python fallback, and the two
  paths must produce byte-identical output for the same input. A codec is
  defined by its C source and its pure-Python implementation together; a
  committed binary that disagrees with both is a defective build of that codec,
  not a codec of its own. Rebuild it from the source and say so in the release
  note, naming the characters that differ; do not give the defect a name.
  - `test/test_b91.py` checks every committed `libbase91-*.so` against the
    alphabet in `src/b91.c`, by reading the binary rather than executing it, so
    one machine covers all three architectures. It also runs the library that
    actually loaded against the pure-Python codec over every byte value and
    random inputs; that check covers only the architecture running the suite,
    which is what makes it the one to run in place on a deployment target.
- This is a pure encoding library, not a crypto or security boundary: there is
  no authentication, ACL, or secret-handling code here. It does not weaken any
  security check because it does not perform one — the encrypted-payload
  handling it packs for transport is the caller's responsibility.
- There is no caching in this codebase today; if one is added, it must only
  cache pure functions of their input and must not be keyed in a way that lets
  stale output leak across different input bytes.
- Precompiled `.so` binaries are committed artifacts, not build output to
  regenerate ad hoc — never let CI or an editable install silently overwrite
  them with a locally-built variant for a different architecture.
